# Decisions

| ID | Date | Decision | Status | Consequence |

| DEC-001 | 2026-08-11 (pre-existing decision, recorded retroactively) | Use Leaflet + OpenStreetMap for the interactive delivery-pin map instead of the Google Maps JS SDK | Accepted | No API key shipped to the browser; avoids Google Places Autocomplete's no-free-tier cost. Swapping in a Google-based map later is possible but not planned. |
| DEC-002 | 2026-08-11 (pre-existing decision, recorded retroactively) | On a dev Mac behind a TLS-inspecting corporate proxy, use a separate local JVM trust store file passed via `MAVEN_OPTS`, instead of modifying the system/JVM-wide trust store | Accepted | Fix is machine-local and non-destructive, but must be redone (or the file relocated) on every new dev machine. |
| DEC-003 | 2026-08-11, implemented 2026-08-13 | Switch H2 from in-memory to file-based (`jdbc:h2:file:./data/bakerydb`) | Accepted | Implemented in `application.yml`; `backend/data/` added to `.gitignore` (contains a real, un-shareable DB file). Verified live: set `storePhone` via `PUT /api/v1/admin/store-settings`, restarted the backend process, confirmed the value was still there on `GET`. Resolves the repeated loss of Store Settings across sessions/machines — see `handoff.md`. |
| DEC-004 | 2026-08-11 | Set the default seeded store coordinates (`StoreSettingsSeeder.java`) to match the store's Google Maps place link pin (`.../maps/place/Home+Cafe+by+Bami/...!3d14.8690823!4d121.0430113...`) — coordinates unchanged (already correct), `storeAddress` kept as the full postal address `"048 Kay Piskal Rd, Tigbe, Norzagaray, 3013 Bulacan, Philippines"` | Accepted (amended) | Resolves Open Issue 1 (degraded address precision) at the seed level. **Amendment:** an initial version of this change set `storeAddress` to the bare place name `"Home Cafe by Bami"`, which a code-review pass caught as a regression — that field is shown verbatim to customers (footer, location banner, order-status page) and sent to Lalamove as the rider pickup-address text, so a bare business name loses street-level detail those consumers need, and it conflicted with the hardcoded address on the contact page. Reverted to the full address string; only the coordinates (already correct) come from the Maps link. |
| DEC-005 | 2026-08-13 | Make `app.ocr.tessdata-path` read from a `TESSDATA_PATH` env var, falling back to the existing hardcoded Windows path | Accepted | Same pattern already used for Lalamove/Google keys (`${VAR:default}`). Lets the Mac dev machine set its own Homebrew tessdata path locally without editing a committed file. Not yet verified on macOS itself — only confirmed the Windows fallback still starts clean. |
